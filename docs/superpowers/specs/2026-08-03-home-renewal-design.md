# ホームページ・ナビゲーション リニューアル設計

## 背景・目的

`docs/01. GEOリニューアル-ホーム.docx` の新コンテンツ構成に合わせて、トップページ (`/`) とヘッダーナビゲーション (`Header.tsx`) を再構成する。

新しいナビゲーション構造:

```
Home - GEO Watcher - GEO 診断 - GEO LAB - 相談する（ボタン）
```

`/why-ascent` `/framework` `/services` の3ページはヘッダーメニューから除外する（ページ・ルート自体は残す。現状のHeader.tsxには元々この3リンクは存在しないため、実質「Home」項目の追加のみが変更点）。

## 対象範囲

1. `src/components/layout/Header.tsx` — デスクトップ・モバイル両方のナビゲーション項目
2. `src/app/page.tsx` — トップページのセクション構成・コピー全面刷新

範囲外（今回は変更しない）:
- `/why-ascent`, `/framework`, `/services` ページ自体（ファイル・ルートは維持）
- `/watcher`, `/shindan`, `/lab` の各ページ内部
- Footer（電話番号は既にFooterに掲載済みのため、Heroには表示しない）

## ヘッダーナビゲーション変更

現状:
```ts
[
  { label: "モニタリングツール", href: "/watcher" },
  { label: "診断ツール", href: "/shindan" },
  { label: "GEO Lab", href: "/lab" },
  { label: "Contact", href: "/contact" },
]
```

変更後:
```ts
[
  { label: "Home", href: "/" },
  { label: "GEO Watcher", href: "/watcher" },
  { label: "GEO 診断", href: "/shindan" },
  { label: "GEO LAB", href: "/lab" },
]
```

CTAボタン（`相談する` → `/contact`）は既存のまま維持。デスクトップ・モバイルメニュー両方に反映する。

## トップページ セクション構成

新しいセクション順序（docxの流れに準拠）:

1. **Hero** — レイアウト維持、コピーのみ差し替え
2. **2ソリューション紹介**（新規） — `WatcherShindanSection` を置き換え
3. **課題提示**（新規）
4. **解決フロー**（新規）
5. **GEO Lab紹介** — 既存 `GeoLabSection` を再利用、リード文のみ差し替え
6. **CTA** — 新コピーの専用CTAセクション（`SeoGeoCTASection`は使わない）

削除するセクション: `SearchShiftSection`（SEO時代 vs AI Answer時代比較）、`ServicesSection`（質問クラスター抽出等の4カード）— docxに対応コンテンツがなく、`/services`ページ自体は残るため機能的な損失はない。

### 1. Hero セクション

レイアウト（左テキスト＋右ContactForm、背景アニメーション、HeroLogoMark）は変更しない。コピーのみ差し替え:

- ラベル: `企業のGEO・LLMO対策を支援`
- H1: `GEO・LLMOの診断とモニタリングツール` / `AI検索上の課題を、次の行動へ`
- 本文: `Ascent GEOは、見込み顧客の課題を可視化するエージェンシー向けの「GEO診断レポートツール」と、自社・競合の変化を継続的に追う「GEO Watcher（GEO・LLMOモニタリングツール）」を提供します。現状把握から提案、改善、効果検証まで、目的に合わせたGEO・LLMO対策を支援します。`
- CTAボタン: `CalendarBookingButton` のみ維持。既存の「サービス資料をダウンロード」ボタンは削除（資料準備後に復活予定 — コード上はコメントアウトで残し、再有効化しやすくする）。電話番号はHeroに追加しない（Footerに既存）。

### 2. 2ソリューション紹介セクション（新規、`WatcherShindanSection`を置換）

- ラベル: `サービス紹介`
- 見出し: `GEO・LLMO対策の目的に合わせて、2つのソリューションを。`
- リード文: docxのリード文をそのまま使用（自社・競合の変化を継続的に追いたい企業には…／見込み顧客の課題を可視化し…）
- 左右カード（既存の白カードスタイル `bg-white border rounded-2xl card-hover` を再利用）:
  - **左: GEO Watcher**
    - サブラベル: `企業のマーケティング・ブランド担当者向け`
    - タイトル: `自社・競合の変化を毎日追い、次の改善へ。`
    - 説明文: `主要AIにおける自社・競合の言及、引用、露出を毎日計測。競合との差や施策前後の変化を継続的に確認し、次に取り組むべき改善テーマを判断できます。`
    - スペックバッジ4つ: `主要7AI` `毎日自動計測` `競合20社まで比較` `過去365日分を保存`
    - CTA: `GEO Watcherを見る →` (`/watcher`)
  - **右: GEO診断レポート**
    - サブラベル: `SEO・Webマーケティング会社の法人営業向け`
    - タイトル: `GEO・LLMO診断データから、初回商談を具体化する。`
    - 説明文: `ブランド名とURLを入力するだけで、見込み顧客のAI検索上の課題と競合との差を可視化。たった数分で、営業提案に使える診断レポートを作成できます。`
    - スペックバッジ4つ: `主要6AI` `プロンプト・競合を自動生成` `自社ロゴ・CTAに変更可能` `提案用レポートを作成`
    - CTA: `GEO診断レポートを見る →` (`/shindan`)

### 3. 課題提示セクション（新規）

- 見出し: `目的によって異なる、GEO・LLMO対策の課題。`
- 左右カード（`SearchShiftSection`のダークカードスタイルを踏襲: グラデーション背景＋ぼかし円）:
  - **左: GEO Watcher（マーケティング・ブランド担当者の課題）**
    - サブ見出し: `AI検索上の自社・競合の変化を、追えていますか？`
    - 説明: `AIごとに言及や引用の状況は異なり、その結果も日々変化します。一度確認するだけでは、施策の効果や競合との差、次に改善すべきポイントを正しく判断できません。`
    - Bullet×4: 複数のAIを横断して確認できていない／競合との差や業界内の立ち位置が把握できていない／施策前後の変化を継続的に追えていない／改善すべきテーマをデータから判断できていない
  - **右: GEO診断レポート（SEO・Webマーケティング会社の法人営業担当者の課題）**
    - サブ見出し: `「AI検索対策が必要です」だけで、商談を具体化できていますか？`
    - 説明: `一般論だけでは、相手企業にとっての課題が見えず、具体的な提案にはつながりません。商談前に、AI上の言及状況や競合との差、次に提案すべきテーマを把握する必要があります。`
    - Bullet×4: 見込み顧客ごとの課題を短時間で調べられない／初回商談で示せる具体的なデータがない／SEO提案にGEO・LLMOの切り口を加えられない／診断結果を次の相談や提案につなげにくい

Bulletは `article-list__item` パターンの再発バグ（AGENTS.md記載）を踏まえ、`<strong>`直下配置を避け、テキストノードのみか`<span>`ラップで実装する。

### 4. 解決フローセクション（新規）

- 見出し: `目的別の課題を、2つのソリューションで解決。`
- 左右カード:
  - **左: GEO Watcher**
    - 説明: `AIごとの差や施策前後の変化を継続的に追うことで、GEO・LLMO対策の効果と、次に優先すべき改善テーマを判断できます。`
    - フローバッジ: `測る → 比べる → 改善する → 確かめる`
    - CTA: `GEO Watcherを見る →` (`/watcher`)
  - **右: GEO診断レポート**
    - 説明: `相手企業ごとのAI検索上の課題と競合との差を、初回商談で示せるGEO・LLMOの具体的な提案材料に変えられます。`
    - フローバッジ: `診断する → 課題を示す → 提案する → 商談につなげる`
    - CTA: `GEO診断レポートを見る →` (`/shindan`)

### 5. GEO Lab紹介セクション

既存 `GeoLabSection` の記事カード構成（Featured大カード＋2小カード＋下部3カードグリッド）はそのまま再利用。見出し・リード文のみ差し替え:

- 見出し: `GEO・LLMO対策を、知識とデータの両面から。`
- リード文: `Ascent GEO LABは、AI検索時代の変化を、調査と実践から読み解くリサーチハブです。検索行動の変化、SEOとGEO・LLMOの違い、AIに引用されるコンテンツの条件、効果測定の考え方など、実務に役立つ知見を公開します。`

### 6. CTAセクション（新規、`SeoGeoCTASection`の代わり）

既存 `CTASection` コンポーネント（`src/components/layout/CTASection.tsx`）の構造を再利用し、新コピー・2ボタンで専用セクションを作る:

- 見出し: `AI検索で選ばれるための一歩を、ここから。`
- 説明: `自社ブランドの変化を継続的に捉えるなら、GEO Watcher。見込み顧客への提案を具体化するなら、GEO診断レポート。診断する。変化を追う。課題を次の改善へつなげる。目的に合った方法で、GEO・LLMO対策を始めましょう。`
- ボタン1: `GEO Watcherを見る` (`/watcher`)
- ボタン2: `GEO診断レポートを見る` (`/shindan`)

## 実装上の注意

- 既存のビジュアルトーン（グラデーションカード、SVGチャート、`text-blue-gradient`、`tag-blue`/`tag-dark`バッジ、`card-hover`/`card-hover-dark`）を可能な限り再利用し、新規セクションもこのデザイン言語に揃える。
- `SectionLabel` コンポーネントは既存のものを再利用する。
- 削除するセクション（`SearchShiftSection`, `WatcherShindanSection`旧版, `ServicesSection`）内で使われるヘルパー（SVGアイコン等）が他で使われていないか確認し、未使用コードは削除する。
- `metadata`（title/description）はdocxのMETA情報を反映するか要確認（今回のスコープ外とし、現状維持。必要なら別タスク）。
- 全ての変更をローカル環境（`npm run dev`）で確認してから次のステップに進む。
